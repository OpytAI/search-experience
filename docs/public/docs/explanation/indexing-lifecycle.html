Indexing lifecycle

From empty OPFS to lexical-ready, optional semantic-ready, and refresh without blocking queries.

Cold start

  1. configure installs collections, schema, fingerprints.
  2. crawl_step loops: dequeue URL, host fetch, host extract, insert pages/chunks into active index.db when not in candidate mode.
  3. embed_step embeds pending chunks; VANN rows appear; semanticReady only when the guest can honestly claim it.
  4. Checkpoints mark lexical/semantic/idle durability points for restore logic.

Refresh

refresh opens a candidate generation on candidate.db while queries still read index.db. When the candidate has pages ≥ 1 and chunks ≥ 1 (and is not truncated), promote copies candidate → active and clears candidate.

Why two files

Readers should not observe a half-built index mid-refresh. Dual databases make “always query active” a structural property rather than a locking hope.
