Configure multi-collection crawl

Declare labeled scopes with seeds and UI prefixes so the palette matches how people think about your site.

Minimal multi-collection config

globalThis.AgentOSSearch = {
  collections: [
    { id: "docs", label: "Documentation", seeds: ["/docs/"], prefix: "docs:", order: 10 },
    { id: "blog", label: "Blog", seeds: ["/blog/"], prefix: "blog:", order: 20 },
  ],
  refreshAfterMs: 60 * 60 * 1000,
};

Fields that change behavior today

  • seeds — absolute or page-resolved start URLs for the crawl queue.
  • id / label / order / prefix / placeholder / limit / minQueryLength — palette.
  • refreshAfterMs — background rebuild cadence (clamped 60s … 7d when set).

Fields carried but not fully guest-enforced yet

includePathPrefixes, excludePathPrefixes, maxPages, sitemaps may be present in BrowserCrawlDefinition. Host path helpers and guest policy are evolving—treat seeds as the hard boundary until your version documents enforcement as complete.

Same-origin rule

Fetch allowlist is the page origin. Extra origins entries only stick if they match that origin. Off-origin indexing is out of scope for the visitor product.
