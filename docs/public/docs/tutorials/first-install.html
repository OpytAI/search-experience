Install the package on a static site

You will put the release tree next to your pages and load one module script. When you finish, the search launcher is on the page and the guest can boot.

What you need

  • A site you control, served over https: or http://localhost (secure context for OPFS and module workers).
  • release.tar from CI or bazel build //:release.
  • Permission to change static hosting (MIME types matter later).

1. Unpack into the static root

Choose the folder your stack already publishes at the site origin:

tar -xf release.tar -C public
# → public/agentos-search/

Vite / Next / Nuxt / Astro use public/. Hugo / SvelteKit use static/. Plain nginx uses the document root. The script URL should become /agentos-search/agentos-search.mjs unless you relocate the package.

Treat the directory as one compatibility unit. Never mix kernel, image, or JS from different builds.

2. Load the entry script once

Put this in a shared layout so every page you want searchable loads the same module:

<script type="module" src="/agentos-search/agentos-search.mjs"></script>

Default behavior crawls same-origin links starting at /. No config object is required for that default.

3. Confirm boot

  1. Open the site in a modern browser.
  2. Press ⌘K or Ctrl K, or click Search.
  3. The palette (or mobile sheet) should open. First visit may show a short boot/crawl status.
If the palette never opens Open Network for agentos-search.manifest.json and agentos-search.mjs. You need HTTP 200 and a JavaScript MIME for .mjs. See the host-static and CSP how-tos if those fail.

What you installed under the hood

You did not start a search process on a server. You published Wasm kernel bytes, a guest image (search-atlas.tar), ONNX weights, and host/worker JS. The visitor’s browser will create a guest machine, call host tools for fetch/extract/embed, and keep the index in OPFS.

Checkpoint

You can open search. Next: run your first real search.
