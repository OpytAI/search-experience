How the runtime fits together

Site search is a guest machine in the browser plus a deliberately thin host. The interesting policy lives inside the guest.

Stack

Page module (agentos-search.mjs)
  → registers mc-site-search, optional SW
  → module worker (agentos-search-runtime.mjs)
      → mc-core + kernel.wasm + search-atlas.tar
      → /svc/searchd  (serviceCall)
      → host tools: fetch | extract | embed.batch
      → OPFS snapshots + SQLite under /var/searchd

Why a guest

AgentOS gives a stamped service boundary. Ranking, journals, and generation promotion are not scattered across React state and ad-hoc IndexedDB schemas. The host is replaceable glue; the guest is the product authority.

Atlas shape

search-atlas is not stock AgentOS atlas/loom/Luau. It is base + sqlite (FTS5/VANN) + eager searchd + /var/searchd. Searchd does not shell out to coreutils, so base is enough.
