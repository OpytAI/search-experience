Ship a warm first visit

Cold crawl on every new browser is honest but slow. You will capture a gzip MCSN after a real crawl and inject it so empty OPFS can restore.

When this helps

Marketing sites and docs with stable seeds: first paint of search readiness matters. When kernel, image, schema, model, protocol, collections, or origin change, restore correctly fails and visitors cold-boot again.

1. Product path ready

bazel build //:release
tar -xf bazel-bin/release.tar -C docs/public
# site config + collections must match what you will ship

2. Capture

bun tools/browser-e2e.mjs \
  --release-dir=docs/public/agentos-search \
  --export-snapshot \
  --out=./warm

Or bun src/publisher/cli.ts --capture --release-dir=… --out=./warm. Output is gzip MCSN only; snapshotSha256 digests compressed bytes.

3. Inject

bun tools/package-prewarm.mjs \
  --release-dir=docs/public/agentos-search \
  --snapshot=./warm/search.snapshot \
  --metadata=./warm/search.snapshot.metadata.json

4. Verify

Clear site data for the origin (or use a fresh profile). Load the site: first open should restore faster than a full crawl when keys match. Application → storage should show OPFS growth without a long multi-minute first index for small sites.

Checkpoint

Warm path is optional and site-specific. Concepts: warm snapshots. Procedure details: prewarm how-to.
