Run your first real search

With the package loaded, learn how typing, collections, prefixes, and selection behave—using this documentation site as the live example when the product path is mounted.

Open the surface

Keyboard: ⌘K / Ctrl K toggles the dialog. Pointer: use the header Search control. On a narrow viewport the same component becomes a full-viewport sheet with a close control instead of Esc-only chrome.

Empty state vs results

With no query, the list stays minimal (“Type to search” when ready). As you type, the worker asks guest /svc/searchd for hits. Status can briefly show loading per collection.

Read a hit

  • Label — preferably the page H1 (extract prefers H1 over a shared site <title>).
  • Secondary — heading, description-like snippet, or path.
  • Preview (desktop) — title, summary, URL facts for the active row.

Prefixes on this site

When multi-collection config is active (as on this docs site with product assets):

docs: architecture
blog: collections

Prefixes scope the query in the palette. They are not a substitute for careful seeds until guest path-prefix enforcement is complete.

Navigate and close

Arrow keys move the active row; Enter opens (or your SPA handler runs). Escape closes on desktop. Sheet mode uses the close button when keyboard chips are hidden.

Checkpoint

You can find and open a page from the palette. Next: configure two collections end-to-end.
