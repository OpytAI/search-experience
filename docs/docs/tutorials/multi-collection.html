Walk through multi-collection search

You will declare two collections with separate seeds and prefixes, reload, and verify the palette shows both sections.

Scenario

Your site has documentation under /docs/ and posts under /blog/. You want both searchable, labeled, and prefix-filterable—without a host-side ranker inventing “boosts.”

1. Write the config

Before the entry module:

<script>
  globalThis.AgentOSSearch = {
    collections: [
      {
        id: "docs",
        label: "Documentation",
        seeds: ["/docs/"],
        prefix: "docs:",
        order: 10,
      },
      {
        id: "blog",
        label: "Blog",
        seeds: ["/blog/"],
        prefix: "blog:",
        order: 20,
      },
    ],
  };
</script>
<script type="module" src="/agentos-search/agentos-search.mjs"></script>

2. Keep the graph small

Crawl BFS-follows same-origin links from each seed. Until guest fully enforces include/exclude prefixes, a link from a docs page to / can pull the whole site into that collection’s queue. Prefer a tight internal graph and explicit seeds (this documentation tree is intentionally nested under /docs/ and /blog/).

3. Verify in the palette

  1. Hard-refresh so config is not stale.
  2. Open search and type a shared word (for example collection).
  3. Confirm separate section headings for Documentation and Blog when both match.
  4. Try blog: alone with a blog-only term—results should stay in Blog.

What the guest stored

Each collection is partitioned in SQLite (pages/chunks keyed by collection_id; VANN uses a collection_id partition). Queries always hit the active index.db for that generation—not a host-built JSON index.

Checkpoint

Two scopes appear as first-class UI sections. Deep field list: configuration. Concept: why collections exist.
